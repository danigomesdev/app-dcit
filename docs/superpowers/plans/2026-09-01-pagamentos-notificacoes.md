# Pagamentos (RH) + Notifications Infrastructure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give RH a `/pagamentos` page to send payment-status notifications to colaboradores (individually or in bulk, filterable by name/team), backed by a new generic `Notification` table and a `team` field on `Employee` — both built to be reused unchanged by the two follow-up sub-projects (web and mobile notification bells).

**Architecture:** New `Notification` Prisma model (generic `type`/`category`, no FK to `Employee`) plus a `team: String?` field on `Employee`. A new `apps/api/src/notifications` module exposes both the RH-sending endpoints and the colaborador-reading endpoints (`GET /notifications/mine`, `POST /notifications/:id/read`) — the reading endpoints have no UI yet, they exist so the next two sub-projects never touch the API again. On the web side, a new RH-only `/pagamentos` page with one Client Component (`PagamentoCategorySection`) per payment category, handling local search/team filtering and the send action.

**Tech Stack:** NestJS + Prisma (SQLite) on the API; Next.js 16 App Router (Server Components + one Client Component + a directly-invoked Server Action) on the web; Jest on the API and `packages/shared-types`; Playwright e2e on the web (the only test layer `apps/web` has).

**Spec:** `docs/superpowers/specs/2026-09-01-pagamentos-notificacoes-design.md`

## Global Constraints

- No monetary value anywhere in a payment notification — every category's message is a fixed status string, never a R$ amount.
- `Employee.team` is free text (`z.string().min(1).nullable()`), not a fixed enum like `cargo`/`nivel` — the team filter's options come from whatever values already exist on colaboradores, never a hardcoded list.
- `Notification.type` is a free string (not a Prisma enum) so the next roadmap item (automatic missed-punch detection) can reuse this same table without a new migration.
- `/pagamentos` is **RH-only** (`role === "rh"`), not `["gestor", "rh"]` like most administrative pages in this app — this is a deliberate exception, confirm it explicitly wherever the role check appears.
- "Already sent this month" is derived only from `Notification` rows within a client-computed date range (same pattern as `/banco-de-horas/equipe`) — no separate status table.
- The category accordion uses the button+chevron pattern from `EmployeeBenefitsGroup` (`apps/web/src/app/(app)/beneficios/employee-benefits-group.tsx`) — never native `<details>`, which renders inconsistently across browsers (established in the Benefícios sub-project).
- The `sendPagamento` Server Action is called directly from a Client Component (not via `<form action={...}>`) — the first place in this codebase doing that; it's a supported pattern, not a workaround, because the send targets (`userIds`) are a client-computed filtered list with no natural `FormData` shape.
- `GET /notifications/mine` and `POST /notifications/:id/read` have no consuming UI in this plan — they exist only for the two follow-up sub-projects (web and mobile notification bells) and are covered by API-level tests only.
- Adding `team` to `EmployeeCreateSchema` changes a TypeScript type that many existing files construct object literals against — every task touching it must land as one atomic, fully-compiling commit (see Tasks 3 and 5), never split partway.

```typescript
import { Injectable } from '@nestjs/common';
import { PrismaService } from '../prisma/prisma.service';
import { PagamentoCategoria } from '@ponto-dcit/shared-types';

const PAGAMENTO_MESSAGE: Record<PagamentoCategoria, string> = {
  salario: 'Seu salário foi depositado.',
  auxilio_home_office: 'Seu auxílio home office foi depositado.',
  vale_transporte: 'Seu vale-transporte foi depositado.',
  vale_alimentacao: 'Seu vale-alimentação foi depositado.',
};

@Injectable()
export class NotificationsService {
  constructor(private readonly prisma: PrismaService) {}

  async sendPagamento(category: PagamentoCategoria, userIds: string[]) {
    const message = PAGAMENTO_MESSAGE[category];
    await this.prisma.notification.createMany({
      data: userIds.map((userId) => ({
        userId,
        type: 'pagamento',
        category,
        message,
      })),
    });
  }

  // start/end: "YYYY-MM-DD" strings computed by the caller (same pattern as
  // /banco-de-horas/equipe) — this service never decides "what month is it
  // now" itself.
  async pagamentoStatus(category: PagamentoCategoria, start: string, end: string) {
    const notifications = await this.prisma.notification.findMany({
      where: {
        type: 'pagamento',
        category,
        createdAt: { gte: new Date(start), lte: new Date(`${end}T23:59:59.999Z`) },
      },
      orderBy: { createdAt: 'desc' },
      select: { userId: true, createdAt: true },
    });
    // A colaborador may have been notified more than once in the range
    // (resend) — keep only the most recent per userId; the desc orderBy
    // above guarantees the first match per userId is already the latest.
    const seen = new Map<string, string>();
    for (const n of notifications) {
      if (!seen.has(n.userId)) seen.set(n.userId, n.createdAt.toISOString());
    }
    return Array.from(seen, ([userId, sentAt]) => ({ userId, sentAt }));
  }

  listMine(userId: string) {
    return this.prisma.notification.findMany({
      where: { userId },
      orderBy: { createdAt: 'desc' },
    });
  }

  async markRead(id: string, userId: string) {
    // Compound where (id + userId) instead of a separate ownership check:
    // updateMany with this where affects nothing if the id belongs to a
    // different userId, so a user can't mark someone else's notification
    // read just by guessing its id.
    await this.prisma.notification.updateMany({
      where: { id, userId },
      data: { readAt: new Date() },
    });
  }
}
```

```tsx
"use client";

import { useMemo, useState } from "react";

import styles from "./pagamentos.module.css";

type Colaborador = { userId: string; name: string; role: string; team: string | null };
type StatusEntry = { userId: string; sentAt: string };

function formatSentAt(iso: string): string {
  return new Date(iso).toLocaleDateString("pt-BR", { timeZone: "UTC" });
}

export function PagamentoCategorySection({
  label,
  colaboradores,
  status,
}: {
  category: string;
  label: string;
  colaboradores: Colaborador[];
  status: StatusEntry[];
}) {
  const [open, setOpen] = useState(false);
  const [search, setSearch] = useState("");
  const [teamFilter, setTeamFilter] = useState("");

  const sentAtByUserId = useMemo(() => new Map(status.map((s) => [s.userId, s.sentAt])), [status]);

  const teams = useMemo(
    () =>
      Array.from(new Set(colaboradores.map((c) => c.team).filter((t): t is string => Boolean(t)))).sort(),
    [colaboradores],
  );

  const filtered = useMemo(() => {
    const query = search.trim().toLowerCase();
    return colaboradores.filter((c) => {
      const matchesSearch = query.length === 0 || c.name.toLowerCase().includes(query);
      const matchesTeam = teamFilter.length === 0 || c.team === teamFilter;
      return matchesSearch && matchesTeam;
    });
  }, [colaboradores, search, teamFilter]);

  return (
    <div className={styles.categoryGroup}>
      <button
        type="button"
        className={styles.categoryHeader}
        onClick={() => setOpen((current) => !current)}
        aria-expanded={open}
      >
        <span className={styles.categoryLabel}>{label}</span>
        <svg
          className={open ? `${styles.categoryChevron} ${styles.categoryChevronOpen}` : styles.categoryChevron}
          viewBox="0 0 24 24"
          fill="none"
          aria-hidden="true"
        >
          <path d="M6 9l6 6 6-6" stroke="currentColor" strokeWidth="2" strokeLinecap="round" strokeLinejoin="round" />
        </svg>
      </button>
      {open ? (
        <div className={styles.categoryBody}>
          <div className={styles.filters}>
            <input
              type="text"
              placeholder="Buscar colaborador..."
              value={search}
              onChange={(event) => setSearch(event.target.value)}
              className={styles.filterInput}
              aria-label={`Buscar colaborador em ${label}`}
            />
            <select
              value={teamFilter}
              onChange={(event) => setTeamFilter(event.target.value)}
              className={styles.filterSelect}
              aria-label={`Filtrar por time em ${label}`}
            >
              <option value="">Todos os times</option>
              {teams.map((team) => (
                <option key={team} value={team}>
                  {team}
                </option>
              ))}
            </select>
          </div>

          {filtered.length === 0 ? (
            <p className={styles.sectionEmpty}>Nenhum colaborador encontrado.</p>
          ) : (
            <ul className={styles.list}>
```

```tsx
function todaySaoPauloDateOnly(): string {
  const parts = new Intl.DateTimeFormat("en-CA", {
    timeZone: "America/Sao_Paulo",
    year: "numeric",
    month: "2-digit",
    day: "2-digit",
  }).formatToParts(new Date());
  const get = (type: string) => parts.find((p) => p.type === type)?.value;
  return `${get("year")}-${get("month")}-${get("day")}`;
}

function firstDayOfMonth(dateStr: string): string {
  return `${dateStr.slice(0, 7)}-01`;
}

  if (!session || session.role !== "rh") {

  const colaboradores = employees.filter((e) => e.role === "colaborador");

  const today = todaySaoPauloDateOnly();
  const start = firstDayOfMonth(today);

    PAGAMENTO_CATEGORIAS.map((category) =>
```
